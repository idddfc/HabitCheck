# 开发日志 — 2026-06-21

## ✅ 已完成

### Android DateTimePicker 三连 Bug 修复

| Bug | 状态 | 根因 | 修复方案 |
|-----|------|------|---------|
| **① 改时间点确定后重复弹出** | 🟢 已修复 | `onValueChange` + `setReminderTime` 触发重渲染 → Android 原生对话框重新弹出 | `onValueChange` 中同时调用 `setTimePickerKey(0)`，同批次渲染卸载选择器 |
| **② 不改时间点确定→重新编辑自动弹出** | 🟢 已修复 | `onDismiss` 未触发时 `timePickerKey` 残留 >0，重新打开 sheet 首帧渲染了选择器 | `useEffect(!visible)` 分支中 `setTimePickerKey(0)` 关闭 sheet 时清理 |
| **③ 修改时间后保存不持久化** | 🟢 已修复 | 保存时 `reminderTime` 状态未及时反映最新值 | 改用 `savedTimeRef` 跟踪最新时间，`handleSave` 从 ref 读取；打开编辑时从 storage 重新读取最新数据 |

### 关键发现
- Android 上 `onValueChange` 与 `onDismiss` **互斥**：点确定只触发前者，取消只触发后者
- `onValueChange` 仅在用户确认时触发一次（非滚轮滚动时），因此可直接在回调中同时更新 state 和关闭选择器
- `expo-file-system` 同步写入后立即读取可能存在未落盘窗口 → 改用 `getHabits(true)` 重新从文件读取
